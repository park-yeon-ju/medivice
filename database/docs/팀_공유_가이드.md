# 팀 공유 가이드 — 누가 무엇을 돌려야 하나

> 작성자 : 박기준 (DA) · 작성일 : 2026-09-02

## 결론부터

**수집·정규화는 DA 한 사람만 돌린다. 팀원은 돌리지 않는다.**

팀원이 각자 수집을 돌리면 각자 인증키를 발급받아야 하고, 호출 결과도 시점에 따라 조금씩 달라진다.
같은 프로젝트에서 사람마다 다른 DB를 갖게 되면 API·FE가 붙일 기준이 사라진다.
그래서 **DA가 한 번 만든 정규화 결과(CSV)를 커밋하고, 팀원은 그것을 DB에 넣기만 한다.**

```
[DA 1명]  check_api → collect → normalize → CSV 커밋
                                              │
[팀원 전원]  git pull → 신규 DB는 setup_db.py --all / 기존 DB는 sql 06→03 실행
```

## 역할별로 실제 필요한 것

| 역할 | 필요한 것 | 해야 할 일 |
|---|---|---|
| **DA** (박기준) | 전부 | 수집·정규화·적재·ERD |
| **BE / API** | 스키마 + 데이터가 든 DB | `git pull` → 아래 3단계 |
| **FE** | Mock API 응답 JSON | DB 불필요. API 담당이 만든 Mock 응답만 있으면 된다 |
| **PM / UX / 발표** | ERD 이미지 + DBML | `dbml/` 파일만 있으면 된다. 파이썬·DB 설치 불필요 |

**팀원 중 파이썬과 PostgreSQL이 둘 다 필요한 사람은 BE·API 담당뿐이다.**
나머지는 아무것도 설치하지 않아도 된다. 이걸 먼저 정리해야 7명이 각자 환경 세팅으로 하루를 날리지 않는다.

## 팀원(BE·API)이 하는 3단계

```powershell
git clone <레포주소>
cd DA_데이터파이프라인

# ① 환경
python -m venv .venv
.\.venv\Scripts\Activate.ps1        # 프롬프트에 (.venv) 가 떠야 한다
python -m pip install -r requirements.txt

# ② 접속 정보만 채우기 (인증키는 필요 없다)
copy .env.example .env
#   PGPASSWORD 만 본인 PostgreSQL 비밀번호로 수정

# ③ DB 생성 + 스키마 + 적재 + 검증까지 한 번에
python src\setup_db.py --all
```

`psql` 명령은 필요 없다. Windows 설치본은 PATH에 등록되지 않는 경우가 많아
파이썬으로 같은 일을 하도록 만들어 두었다.

`collect_dur_api.py`는 **돌리지 않는다.** 인증키도 필요 없다.

## 커밋하는 것 / 안 하는 것

| | 경로 | 이유 |
|---|---|---|
| ✅ 커밋 | `src/`, `sql/`, `dbml/`, `docs/`, `requirements.txt` | 코드와 설계 산출물 |
| ✅ 커밋 | `data/normalized/*.csv` | **팀원이 API 없이 같은 DB를 만들 수 있게 하는 핵심** |
| ✅ 커밋 | `data/endpoints.json` | 확정된 엔드포인트. 팀이 공유할 가치가 있다 |
| ❌ 금지 | `.env` | **인증키가 들어 있다.** `.gitignore`에 있지만 항상 확인할 것 |
| ❌ 제외 | `data/raw/` | 용량이 크고 재수집 가능하다 |
| ❌ 제외 | `.venv/` | 각자 만드는 것 |

### 표본 데이터를 실수로 공유하지 않기

`data/normalized/_SOURCE.txt` 에 `SAMPLE` 인지 `REAL` 인지가 기록된다.

- `normalize.py` 는 표본이면 큰 경고 배너를 띄운다.
- `load_postgres.py` 는 적재 전에 어느 쪽인지 알려 준다.

**`SAMPLE` 상태의 CSV를 커밋하면 팀 전체가 가짜 DUR 규칙으로 데모하게 된다.**
푸시 전에 이 파일이 `REAL` 인지 반드시 확인할 것.

## 용량이 걱정된다면

정규화된 CSV가 수십 MB를 넘으면 GitHub에서 경고가 뜬다. 두 가지 방법이 있다.

1. **덤프로 대체** — `pg_dump -U postgres -d medivice_db -F c -f medivice.dump` 로 만들어
   릴리즈에 첨부하고, 팀원은 `pg_restore -d medivice_db medivice.dump` 로 복원한다.
2. **판정에 쓰이는 품목만 남기기** — DUR 규칙에 등장하는 `ITEM_SEQ` 로 허가정보를 걸러
   수집 범위를 줄인다. 3일 프로젝트에서는 이쪽이 더 실용적이다.

## GitHub 레포는 채점 항목이다

제출 가이드 §4가 **"GitHub 레포 링크 + 커밋 흔적 캡처"** 를 요구한다.
DA 혼자 전부 커밋하면 "역할 분담"의 증거가 약해진다.
**각 담당이 자기 산출물을 자기 계정으로 커밋**하도록 나누는 편이 좋다.

| 담당 | 커밋할 것 |
|---|---|
| DA | `src/`, `sql/`, `dbml/`, `data/normalized/` |
| API | `*-API.yml` (OAS 명세), Mock 응답 |
| FE | 화면 코드, Mock 연동 캡처 |
| PM | `README.md`, R&R 표, 설계문서 |
